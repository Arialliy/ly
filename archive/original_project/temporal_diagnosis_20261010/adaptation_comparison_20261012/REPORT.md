# 适配设置对照：监督、数据曝光与更新过程

完成日期：2026-10-12，Asia/Shanghai。本轮只整理已有记录，并在CPU比较发布/最终权重；没有新增训练、模型前向或预测推理。

**研究目标已固定为：解决真实场景中可重复的持续漏检，同时约束背景代价和原有检出的退化。** [当前目标与启动条件](../stage1_goal/RESEARCH_OBJECTIVE_CURRENT.md)明确取消“原结构必须先微调到优于发布权重才能设计结构”的隐含要求。需要公平、可解释的比较，以及候选对发布系统实际失败的改善；总匹配数不能替代这两项。

**本轮结论：两条适配路径只有发布权重和512步终点，没有中间检查点。不能定位退化何时发生，也不能事后选择一个未保存的早期工作点。现有日志中最明确的可检验差异是：相同的385个空标签窗口，在近似Soft-IoU中没有直接损失梯度，在top1中仍有背景负监督。** 因此只登记一个“空标签窗补入已有负监督”的适配检验，本轮不实施。它不解释top1自身失败，也不是时序结构创新。

每次更新含两个不同来源，所以“含来源更新数”之和为1,024而不是512。来源和窗口位置由冻结计划关联，实际正框数、背景像素数来自训练日志。两组plan、selection和共用构造源码哈希相同，2,048个逐窗正框计数一致；**top1当时没有逐batch输入哈希，不能宣称已直接完成top1–近似控制逐字节输入核对。** 本轮没有为补记录缺口重放图像。

top1候选背景像素曝光968,194,086，实际选中9,682,738；近似控制有效像素978,568,892，其中正9,360,858、负969,208,034。负标签计数不等于直接负梯度数量或梯度强度。两配方的有效负域也不完全相同。

1,536个目标中心裁剪窗均有正例；512个随机裁剪窗中385个无正例。这385窗占全部曝光18.80%，出现在179次更新中，其中16次四窗全空。来源对数接近不等于对象曝光均衡；反过来，对象数不均衡也不能单独判定采样偏置是根因。训练与开发在序列名和DJI前缀上互斥，尚不能据此证明物理场景独立，两个开发片段已经用于多次设计决策。

## 3. 现有记录能否定位退化过程？

| 问题 | 可用证据 | 本轮能否回答 |
|---|---|---|
| 是否曾在早期预算内恢复，后来退化？ | 两组均只保存最终512步；保存代码在训练循环后单次写权重 | 不能；没有中间状态可供评价，不重训补曲线 |
| 是否从最早更新就发生背景扩张？ | 每步只有变化裁剪上的训练损失／梯度 | 不能；损失不是固定开发集M/U/A |
| 训练与开发是否同方向或同时退化？ | 无这两组权重的训练来源M/U/A路径；开发也只有起终点 | 不能；其他方法的训练来源预测不替代本组轨迹 |
| 有没有确切的监督行为差异？ | 同一16个全空batch中，top1梯度均非零，近似控制均0 | 有；限定为当前损失梯度差异 |
| 能否由参数位移判断应降低学习率？ | 终点位移4.77%／9.15%，优化器和输入计划相同 | 不能；损失不同，且缺少位移与检测变化的中间联系 |

16个全空更新为27、29、30、36、54、72、111、114、118、128、195、285、301、443、467、469。近似控制各步loss=1、grad_norm=0；top1对应步grad_norm范围0.000478846–52.0774，均有负梯度。**零当前损失梯度不等于没有参数更新：Adam历史动量及weight_decay仍可能更新权重。**

按固定连续64步分箱，近似控制空标签窗数量依次为71、48、46、58、38、30、45、49，合计385；它贯穿训练，不是末期才出现。训练损失／梯度分箱表保留在[过程记录](parts/process.md)。因为每步来源与裁剪变化，不将分箱均值画成固定测试集性能曲线，也不比较不同目标函数的总loss高低。

## 5. 只选择一个未运行的适配检验

**X：近似控制中，空标签窗口是否实际贡献背景负监督。** 选择依据是385窗／16个全空更新的直接日志和损失形式，不是只看终点M增加、U增加后猜测学习率或采样。

后续若执行，从相同发布权重重新开始；保留原二值标签、掩码、所有有正窗的masked官方Soft-IoU、原512步数据计划、全部参数更新、BN运行统计、Adam/LR、四窗等权，以及最终512检查点和O/S、0.5评价。**仅空标签窗改用已存在的top-1%背景softplus负项，系数1、比例1%，不扫描参数。** 完整定义见[唯一后续检验](NEXT_ADAPTATION_TEST.md)。本轮只登记，没有实现或运行。

这项检验回答“让本来被曝光却没有直接损失梯度的空标签窗参与背景监督，能否改变恢复—保持—背景取舍”。即使有效，也只是适配比较条件的改善，不是新时序模块或官方代码错误的证明。top1已经给这些窗负监督却仍失败，因此这不能解释所有适配失败，也不保证足够解决研究问题。

结果必须同时面对未改近似控制、top1与发布权重；即使U相对19,446明显下降，仍须检查冻结漏检实际恢复、原成功保持和背景各项代价。新增非零梯度、loss下降或M上涨都不是成功标准。没有证据支持另开降低学习率、冻结主干、蒸馏、采样修改或第二种loss搜索，本轮不登记这些分支。

## 6. 本轮结束点

适配设置已被明确到实际监督、来源曝光、参数更新与证据缺口。没有要求先把原结构调到优于发布权重；下一次结构设计仍需明确失败条件、近期机制、额外信息／约束、简化控制。**BC-TPro继续停止，本轮监督近似控制继续保留原失败结果。**

本轮不扩大诊断清单，不重跑历史实验补中间曲线。目标已固定，唯一适配假设已登记；尚未取得背景受控的成功方法，也没有将持续漏检的原因归于某个时序算子。
