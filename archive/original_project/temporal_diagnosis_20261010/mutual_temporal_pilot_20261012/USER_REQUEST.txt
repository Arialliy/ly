**下一步应进入“实现一个固定候选—完成最小对照—按结果决定去留”的阶段，不再改变研究问题，也不同时尝试多种网络。**

本轮唯一候选仍是：

> **在 DeepPro‑Plus 的唯一 TPro 之前，加入“可拒绝的双向核验时序聚合”，检验能否从参考帧中选择更可靠的信息，恢复原来的漏检，同时控制背景代价与新增丢失。**

**首轮最多三组正式训练：原结构控制 E0、单向聚合 E1、双向核验 E2。** 下文将实现规格、实验顺序和判断条件固定下来。这里给出的是待执行方案，不代表对应机制已经有效或新颖性已经成立。

## 一、先冻结一页实验协议：这一轮只回答两个问题

### 问题一：增加跨帧局部信息，是否有用？

比较 **E1与E0**：

> 在相同监督和训练曝光下，显式聚合邻帧局部特征，能否比原结构恢复更多原漏检，而不是仅仅产生更多预测？

### 问题二：双向核验，是否比普通聚合更好？

比较 **E2与E1**：

> 在相同输入、参数容量和训练条件下，核验跨帧对应关系，能否改善恢复、保持与背景成本之间的取舍？

这两个问题必须分开。E2优于发布权重，但不优于E1，只能支持新增聚合路径有用，**不能支持双向核验是核心贡献**。

协议中继续冻结：原发布权重、训练来源与曝光计划、512步更新、BN运行统计设置、O/S安排、阈值0.5、组件生成与实际匹配规则。已有失败集合和成功保护集合不重新挑选。

**已经登记的空窗负监督配方作为E0/E1/E2的共同监督。** 不根据E0结果临时更换E1/E2的损失。若E0已经按完全相同协议完成，直接复用。

## 二、模型首版：一个实现，两个工作模式

### 1. 接入方式固定，不再修改TPro内部

公开DeepPro‑Plus的实际路径是：

```text
conv_in → layer1 → 特征维度变换 → 唯一 TPro → 预测头
```

本候选放在`layer1`输出之后、维度变换之前。公开实现此处为32通道全分辨率特征；本地代码仍以你的冻结版本为准。[raw.githubusercontent.com](https://raw.githubusercontent.com/TinaLRJ/DeepPro/main/networks/models/DeepPro-Plus.py)

```text
输入窗口
   ↓
原 conv_in、layer1
   ↓
新增聚合模块：single 或 mutual
   ↓
原维度变换
   ↓
原唯一 TPro
   ↓
原预测头、原五窗融合
```

建议只实现一个类，通过`mode="single"`与`mode="mutual"`切换。**不要分别写两套容易出现隐性差别的网络。**

TPro原有分组时间线性映射、归一化和通道融合保持不变。该映射本身没有显式邻帧空间搜索，但这不等于整个DeepPro‑Plus没有空间信息或内容适应能力。[GitHub](https://raw.githubusercontent.com/TinaLRJ/DeepPro/main/networks/layers/TPro.py)

### 2. 首版结构参数

| 项目 | 建议固定规格 |
|---|---|
| 输入、输出 | 相同的 \([B,C,T,H,W]\)，不改变分辨率 |
| 查询位置 | 全部空间位置，不用检测分数筛选 |
| 参考帧 | 当前窗口内的 \(t-1,t+1\)，越界则屏蔽 |
| 描述子 | 单组低维投影，首版固定为8维 |
| 前后向计算 | 共享描述子投影，避免增加一套反向编码器 |
| 搜索范围 | 用训练来源的相邻帧位移统计，在训练前固定 |
| 拒绝机制 | 候选集合加入一个空选项；E1、E2完全相同 |
| 输出方式 | 特征差异的残差修正 |
| 初始化 | 仅输出投影零初始化，其余新增参数正常初始化 |
| 新增监督 | 无对应标签、轨迹损失、光流损失或伪标签 |

搜索半径不能根据开发集哪几个目标恢复得好来调整。训练框或轨迹只能提供**粗位移范围估计**，不能当作精确像素对应。

同样，参考位置不按0.5筛选，否则原本低响应的目标可能根本无法使用新分支。

### 3. 两个模式只改变聚合权重

对当前位置 \(x\) 和参考位置 \(y\)，计算前向概率：

\[
p_{t\rightarrow s}(y\mid x),
\]

候选包含局部位置和空选项。反向概率为：

\[
p_{s\rightarrow t}(x\mid y).
\]

**E1单向控制：**

\[
w^{(1)}_{ts}(x,y)=p_{t\rightarrow s}(y\mid x).
\]

**E2双向候选：**

\[
w^{(2)}_{ts}(x,y)
=
p_{t\rightarrow s}(y\mid x)
p_{s\rightarrow t}(x\mid y).
\]

两组都使用：

\[
\Delta F_t(x)=
\frac{1}{|\mathcal S_t|}
\sum_{s\in\mathcal S_t}
\sum_{y\in\mathcal N(x)}
w_{ts}(x,y)\,[V(F_s(y))-V(F_t(x))],
\]

\[
\widetilde F_t(x)=F_t(x)+W_o\Delta F_t(x).
\]

没有合法参考帧时，修正定义为零。聚合过程中不把非空权重强制重新归一化为1，保留“不采用参考信息”的能力。

**双向概率必须各自正确归一化。** 可以复用共享相似度，但不能把已经归一化的前向概率直接转置，当作反向概率。

### 4. 一个必须提前承认的混杂因素

双向概率相乘，既改变信息来源，也会降低信息注入量。

例如，假设有25个候选位置和1个空选项，所有概率均匀：

\[
\sum_y w^{(1)}=\frac{25}{26}\approx0.962,
\]

\[
\sum_y w^{(2)}=\frac{25}{26^2}\approx0.037.
\]

**因此，E2背景更少，可能只是新增分支被压小了，不一定是对应选择更准确。**

这一点不需要马上增加训练组，但必须纳入后面的机制检查。

## 三、正式训练前，只做实现测试与资源检查

这一阶段不要评价开发集涨点，也不要据此调结构。目标只是确认实现符合设计。

| 检查 | 通过条件 |
|---|---|
| **初始化等价** | 输出投影为零时，原模型与接入模型输出一致到预定数值容差 |
| **梯度启动** | 输出投影能够更新；其更新后，描述子和关联路径能够获得梯度 |
| **人工对应测试** | 对人为指定的关联分数，前向、反向、空选项和索引计算符合公式 |
| **边界测试** | 首尾帧、图像边界、无合法候选均无越界或NaN |
| **分块一致性** | 非零修正状态下，整图和分块输出一致到预定容差 |
| **资源检查** | 实际分辨率和40帧输入下，训练与推理资源可接受，额外成本完整记录 |

有两个实现细节值得特别注意。

**零初始化时，不要要求所有新增参数在第一步都有非零梯度。** 当 \(W_o=0\) 时，前面的关联参数可能暂时没有来自该分支的梯度。需要检查的是输出投影更新后梯度能否继续传播。也不要把所有新增层同时置零，造成无法启动。

**双向核验需要更大的分块边界。** 前向从 \(x\) 搜索到半径 \(r\) 内的 \(y\)，反向归一化还要查看 \(y\) 周围半径 \(r\) 的位置。因此，在已计算的特征图上分块，中央输出可能需要最多 **\(2r\)** 的空间外围特征；若从原图分块，还要考虑前端感受野。不能沿用单向搜索的边界而不验证。

这里的人工测试应人为设置已知分数，不是要求一个尚未训练的匹配器自动识别合成目标。

全分辨率关联的成本主要随 \(THW(2r+1)^2\) 增长。**参数少不等于计算轻。** 不要因为同样使用五窗，就宣称总预算相同。

## 四、正式训练：只运行E0、E1、E2

| 编号 | 网络 | 共同监督 | 该组的作用 |
|---|---|---|---|
| **E0** | 原DeepPro‑Plus | 已登记的空窗补充负监督配方 | 隔离本轮适配因素，建立同监督参照 |
| **E1** | 原网络＋单向聚合 | 同E0 | 检验显式局部跨帧聚合 |
| **E2** | 原网络＋双向核验 | 同E0 | 检验反向核验的独立作用 |

三组都从同一发布权重开始。E1/E2新增参数使用相同初始状态，数据顺序、裁剪、窗口曝光、优化器及BN设置保持一致。**不要在这轮顺手冻结骨干或引入辅助损失。**

保存固定节点，例如0、128、256、384、512步，但**主结果仍为预定512步终点**。中间检查点用于检查训练路径，不事后挑选最优节点替代失败结果。

日志不必做成庞大系统，新增模块至少记录四类量：

> 空选项概率、非空权重总量、修正量相对原特征的范数、输出投影与关联参数的梯度。

它们用于区分“分支正常工作”“几乎完全关闭”“修正量异常放大”等情况，不能替代检测结果。

## 五、训练完成后：同时验证检测效果与时序机制

### 1. 检测效果表：直接沿用已有评估器

每个模型分别报告O、S，至少包含：

| 结果类别 | 要报告的量 |
|---|---|
| 整体检测 | 实际匹配 \(M\)、相对同安排发布权重的新增和丢失 |
| 原失败恢复 | 冻结4,342个低响应目标帧的恢复数、轨迹数、来源分布 |
| 持续性 | 固定轨迹观察范围内的漏检段变化 |
| 原成功保持 | 646个双侧成功对象的保持，区分仅一侧失败和两侧失败 |
| 背景成本 | \(U\)、框外前景像素、未匹配组件面积 |
| 计算成本 | 参数、峰值显存、实际推理耗时 |

**连续漏检必须在同一个完整观察范围内计算。** 缺标、帧间断或原筛选空缺如何打断序列，继续沿用已有规则，不能只保留改善片段。

这些仍然是开发诊断。原报告已经明确，组件峰值点匹配和未匹配组件不能直接称为论文Pd/Fa，旧校准材料也不是独立测试集。PILOT_RESULTS PILOT_RESULTS

### 2. 机制检查A：保持权重总量，只改变“从哪里取信息”

在训练好的E2上，不重新训练，计算：

\[
m_{ts}(x)=\sum_y w^{(2)}_{ts}(x,y).
\]

然后将同样的总权重按单向概率重新分配：

\[
w^{(\mathrm{mass})}_{ts}(x,y)
=
m_{ts}(x)
\frac{p_{t\rightarrow s}(y\mid x)}
{\sum_{y'}p_{t\rightarrow s}(y'\mid x)}.
\]

没有非空候选时设为零。其他特征、参数和输出操作不变。

这个诊断回答：

> **在近似相同的信息注入权重总量下，双向核验选择的位置是否更有价值？**

若实际恢复与背景表现几乎不变，当前证据更支持“控制注入量”，而不是“选择了更可靠的对应位置”。

这里保持的是权重总和，不保证修正特征范数完全相同。因此它是机制诊断；若后续要作强归因，还需要同预算重训的对应控制。

### 3. 机制检查B：新增分支是否真的需要邻帧信息？

同样在固定E2权重上，把新增分支的参考特征替换为当前帧的局部特征，其他路径不动。

它回答：

> 新增模块的收益是否依赖额外的跨帧信息，而不只是一个空间特征处理分支？

需要明确：DeepPro‑Plus前端本来就有时空处理。这个检查只移除了**新增模块的显式参考帧输入**，不能把整个模型称为“单帧控制”。公开前端结构支持这一限制。[raw.githubusercontent.com](https://raw.githubusercontent.com/TinaLRJ/DeepPro/main/networks/models/DeepPro-Plus.py)

训练后输入替换也存在分布变化，因此不能单凭性能下降就完成因果证明；它应与E0/E1/E2对照和轨迹级信息来源检查一起解释。

### 为什么必须检查背景对应？

**背景也能形成稳定、双向一致的对应。** 2026年的运动解耦研究就专门讨论了全局一致背景运动与虚警之间的关系。因此，“往返一致”只能作为参考可靠性的候选约束，不能当作目标身份标签。[arXiv](https://arxiv.org/html/2606.15286)

使用已有标注解释信息来源时，应保留“同一目标区域、其他目标区域、标注框外、归属不确定”四种情况。粗框不能提供精确像素对应真值，注意力落入框内也不自动证明该信息产生了恢复。

## 六、何时确定主线，何时停止？

建议按下表决策，不再因为一次失败就追加模块。

| 结果 | 决策 |
|---|---|
| E0改善，E1/E2没有进一步价值 | 保留训练控制；本结构候选停止 |
| E1有效，E2不优于E1 | 保留普通聚合作为简单基线，放弃双向核验主张 |
| E2背景下降，但等权重总量诊断效果相近 | 主要证据是注入强度控制，不能声称对应选择得到改善 |
| E2恢复目标更多，但仍超背景预算或明显损害保持 | 当前版本未达到研究目标，不升级为主线 |
| E2满足检测约束，并在合理取舍下优于E0/E1，机制检查也支持 | 进入成对多seed复测；重现后确定为主要候选 |
| 多seed有效，但新来源不成立 | 结论限定为局部适配，尚不能主张稳定泛化 |

### 本轮继续沿用的硬边界

**阈值0.5、共同 \(U\le4015\)、固定信息访问和评价规则不变。** O、S分别比较，不逐片、逐帧挑选较好的安排。

但通过共同U预算，不代表相对发布S的背景成本没有增加。相对S主张“成本不增”，仍需对照其 \(U=3967\)、框外前景38,641以及既有面积统计。

原成功保持容差按你的实际登记执行。上一版提出的“44帧、10轨迹、最多6个保持损失”只是建议的筛选尺度，**不是文献给出的有效性界限，也不能追认为已经冻结的历史规则**。不要用这几个整数替代完整检测取舍和重复性证据。

首轮出现正向结果后，再用两个预先固定的新seed成对复测E0/E1/E2。所有控制一起重复，不能只重跑完整模型。之后冻结方法，再按现有规则使用未参与设计的新来源或确认材料。

## 七、这轮应产出什么？

建议固定为四项交付，而不是继续积累新的诊断清单：

| 交付 | 内容 |
|---|---|
| **实验协议** | 网络规格、共同监督、种子、曝光、预算、检查点与判定规则 |
| **单一模块实现与测试记录** | `off/single/mutual`模式；初始化、梯度、边界、分块及资源检查 |
| **三组结果对照** | E0/E1/E2的恢复、保持、背景与计算成本 |
| **机制与去留报告** | 等权重总量诊断、参考帧替换诊断，以及是否值得继续 |

**执行顺序就是：冻结协议 → 完成模块与实现测试 → 运行E0/E1/E2 → 检查检测取舍 → 检查机制必要性 → 通过后才扩展重复和新来源。**

这轮要确定的不是“又加了一个模块是否涨点”，而是：

> **在你的真实失败集合上，双向核验能否比普通跨帧聚合更可靠地利用参考信息，并把这种差异转化为背景受控、原成功损失可接受的实际检出恢复。**

**只有这条证据链成立，才把它定为论文主线；否则停止该候选，而不是继续叠加结构维持原假设。**
