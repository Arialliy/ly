# 从错误结果定位失败环节：窗口依赖、峰提取与持续低响应

2026-10-11。只使用原发布权重的已有输出、两段已用开发片段DJI_0026_2和DJI_0067_2；没有训练、新模型前向或确认集评估。固定阈值0.5，覆盖全部5,200个既定几何小目标帧。历史结果保持不变。

**本轮已把主要错误分开：54个新增丢失全部失去了原成功窗口，47个在新安排下框内响应不足、7个有前景却无合格峰；5个原融合失配则是峰提取问题；4,391个全窗失败中，4,170个甚至在最有响应的已测窗中仍低于0.001。三者不能统称“有害上下文抑制”，也不应由同一个提高响应的方案处理。**

本轮交付：[错误环节表](stages/REPORT.md)、[主要失败条件表](conditions/FAILURE_CONDITIONS.md)、[路线选择记录](ROUTE_DECISION.md)。完整视觉与指标证据另见文末。

## 1. 74个为什么得到，54个为什么丢失

这里的“为什么”先定位处理流程，不把成功窗被移除直接等同于某种物理证据被移除。

|队列|目标帧|序列内轨迹|连续源帧观察事件|确认的处理环节|
|---|---:|---:|---:|---|
|新增|74|21|40|73个由新加入窗口提供实际匹配；1个修复原融合的峰失配。|
|丢失|54|21|36|原来全部成功窗都被移除，新安排没有任何单窗实际匹配。|
|两安排共同成功|646|43|139|两边各有成功窗，不代表全部可用窗都成功。|
|全部可用诊断窗失败|4,391|123|759|没有任何已测窗口成功；与两安排均失败4,426不同。|
|原五窗成功、融合失配|5|3|4|高响应像素保留，融合后零个组件峰落入原目标框。|

新增、丢失轨迹有交集，合计29条，不是42条独立轨迹。5个融合失配与新增组重叠1个，本轮重点集合去重后132个对象帧、91个序列帧。事件由连续的合格源帧定义，资格筛选、缺帧或状态变化会打断，不是独立物理事件。

54个丢失可准确分为：**47个新融合框内最高响应<0.5；7个框内有超阈值像素，但所属组件的峰在框外。** 没有“新安排中单窗仍能匹配，却被新融合吞掉”的端点案例，也没有因仍有合格峰而在匹配分配中竞争失败的案例。

74个新增的原失败状态是70个框内低响应、3个高响应无峰入框、1个原单窗成功但融合峰失配。因此大部分交换确实伴随框内阈值命中的出现/消失，并非都由点匹配规则产生。

同一窗口在两个安排中直接复用同一缓存数组；两边融合逐像素重构相等，排除了“共享窗口重复执行得到不一致输出”的解释。这里仍未分离内容改变和当前帧槽位改变，更未确认运动、遮挡或相机运动是原因。

## 2. 5个融合失配不是像素响应塌缩

|位置|确认的变化|
|---|---|
|0026 / 源帧147 / 轨迹400005|原成功峰和新框外峰都为1.0，按行优先顺序打破平局后选中框外峰；面积25→40。|
|0067 / 源帧74、75 / 轨迹7701908|成功窗中原本分离的2个/3个组件在融合中连接，框外峰更高；面积6→35、6→30。|
|0067 / 源帧142 / 轨迹7701917|组件像素集合完全不变，面积22→22；近饱和概率约1.19×10⁻⁷差异改变最高峰位置。|
|0067 / 源帧144 / 轨迹7701917|组件扩展2个像素，框外峰更高；未证明多个旧组件合并。|

只有2例有直接的多组件合并证据，不能将5例都写成组件合并。5例原前景均保留，也均保留bbox中心邻域命中和框内前景命中。它们首先是“每个预测组件只取一个最高峰”这一诊断输出规格的定位损失。[原图、分数图及裁剪数据](stages/fusion_trace_figures/MANIFEST.json)

官方固定提交的ShootingRules不使用这一预测峰匹配：它对标签连通区域检查邻域前景，并用标签扩展域外前景像素计背景成本。因此，**这5例不能作为官方Pd因max融合下降的证据。** RGB-T加载器实际读取segmentations二值支持域，并非直接读取bbox中心；作者用于评价的实际标签尚未获得。本轮中心邻域代理只能用于规则对照，不能改称官方Pd/Fa。[源码与标签边界核查](metrics/METRIC_AUDIT.md)

## 3. 4,391个全窗失败，主要是哪种输出失败

|在覆盖当前帧的所有已测窗中，对框内最高响应再取最大|对象帧|占4,391|
|---|---:|---:|
|<0.001|4,170|94.97%|
|[0.001,0.01)|68|1.55%|
|[0.01,0.1)|46|1.05%|
|[0.1,0.5)|58|1.32%|
|≥0.5，但所有窗均无实际匹配|49|1.12%|

前四行合计4,342，占98.88%。最大响应的中位数约4.31×10⁻⁶；<0.001组涉及116条轨迹。全失败并非主要由紧贴0.5阈值的一小段分数造成，但这不证明降低阈值永远无用；任何阈值变化仍须同时检查背景。这里“所有窗”只指覆盖当前帧的已测窗口；4,391例中695例只有1个可用诊断窗，不能把它们计作跨上下文不稳定证据。

这一步确定了**输出层主要是持续低响应**，尚未证明低响应的物理或训练原因。16个预登记/明确补充的图像例只用于可判读性和局部结构核查，不估计4,391例的真实可见性比例，也不能替代训练覆盖调查。

其中49个高响应失配全部来自0067，按标注类别为36行人、10骑行者、3汽车。仅在原五窗最终图中则是33个高响应失配，在对称最终图中是36个；49包含额外诊断窗口，三者分母同为4,391，输出统计口径不能替换。

已实际逐图核查16个全失败样本及4个稳定参照。0067两例船标注框内能分辨局部暗结构，但响应仍弱；0026同一400008轨迹的稳定成功帧82/90与全失败帧98都有弱浅亮团外观。桥侧小目标与长边缘难分，稳定成功参照中也存在相似外观。它们说明不能单凭当前图像模糊程度统一解释全部失败；真实可见时长、遮挡、相机及物理运动仍未确认，不由16例推算总体比例。[逐例视觉核查](visuals/ALL_FAILURE_REVIEW.md)

|条件|当前观察|可以支持的判断|

|图像坐标运动|0067新增/丢失/共同成功的原参考集合相邻中心位移中位为1.41/1.50/1.50像素|增损组高度重合，不能将丢失统一归为某个速度范围。|
|最近邻中心距离|0067新增/丢失/共同成功中位为11.60/11.14/12.65像素|池化密度差不能直接当跨场景机制；0026全失败组反而更远。|
|标注存在|全窗失败中2,563个在原安排的所有覆盖窗里均有40帧轨迹标注|标注连续存在也可能低响应，但不证明真实可见或物理静止。|

覆盖次数也不是全部解释：新增中52个、丢失中44个的原/新覆盖次数相同；新增有10个覆盖变少，丢失有5个覆盖变多。最晚访问更早/相同/更晚的新增为43/12/19，丢失为18/14/22。不能把改善简单说成多看未来或多给窗口。[覆盖描述](COVERAGE_DIAGNOSTIC.json)

已为128个增损对象寻找相近稳定参照：422个严格稳定对象池中117个配对成功、11个无满足条件的参照，实际只使用60个唯一参照且允许复用。主条件表仍使用646共同成功全组；配对不是因果匹配或独立样本检验。[条件与对照完整定义](conditions/FAILURE_CONDITIONS.md)

## 5. 固定四窗、每次替换一窗的最小验证已执行

按完整覆盖约束预先登记O→I1→I2→S路径，每步只有一个起点改变；都是五次40帧前向的离线方案。不能直接先将36换成24，否则64..71会没有窗口覆盖。

|安排|五窗起点|小目标匹配|对前一步新增/丢失|未匹配组件|框外前景像素|
|---|---|---:|---:|---:|---:|
|O|0,36,72,108,120|700|参照|4,015|38,368|
|I1|0,36,72,96,120|713|32/19|4,026|38,548|
|I2|0,36,60,96,120|708|16/21|4,031|39,290|
|S|0,24,60,96,120|720|26/14|3,967|38,641|

每一步都有新增和丢失，I1/I2还超过原未匹配组件预算，未通过重选阈值回避。这个路径把20净增分为13−5+12，但边际效应依赖另外四窗及替换顺序，不是唯一因果分解，更没有分离内容与槽位。

另有一个有用的反例：I1中0067源帧106、轨迹7821902仍保留成功的72窗，但加入96窗把原本分离的两个组件连接，峰移到邻近对象处而失配。这是中间安排的新增输出提取失败。**“最终54个丢失都失去原成功窗”不能扩写为任意安排都没有融合失败。** [逐次替换结果](one_replacement/REPORT.md)

|原安排→对称安排，320帧|变化|
|---|---:|
|全部预测组件|7,276→7,339，增加63|
|全部目标匹配组件|3,261→3,372，增加111|
|未匹配组件|4,015→3,967，减少48|

未匹配组件减少是因为成功匹配增加得更多，并非总组件减少。未匹配组件面积95分位还从41变为45。因此上一轮的同背景预算局部改善，仅对当时冻结的未匹配组件口径成立，不能称相同官方Fa下已经改善。

并行代理也保留了得失：小目标中心邻域命中625→642，新增67/丢失50；框内任意像素命中745→771，新增79/丢失53。数字不同，不能互相替代或挑一个最好看的。实际论文指标仍缺作者评价标签。[完整指标与背景核查](metrics/METRIC_AUDIT.md)

## 7. 本轮后的路线选择

优先继续解释**成功窗口依赖**，同时把大规模持续低响应保留为另一候选；不将少量峰提取失败当成74/54交换的主要原因。接下来的关键是：成功窗比失败窗提供了什么可用证据，以及这种条件能否在预定新来源上重复。当前尺度、运动和密度表还没有给出统一答案。

具体模型或数据改进仍由证据触发：输出规则问题先固定分数图检查候选；时间覆盖问题先核查内容与位置；持续低响应先核对可判读性、参考信号和监督对应。不能仅凭低分就补数据，也不能对已有接近1的前景继续追求更高响应。[路线选择及可证伪验证](ROUTE_DECISION.md)
