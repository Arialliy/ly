# N0 / N1 / N2 固定评价协议

本轮仅评价附件授权的三个新增分支信息模式。旧 E0 / E1 / E2 不作为本轮同训练结构控制，不补跑旧实验。评分实现复用 `../top1_background_control_20261011/evaluation_code/evaluate.py` 及其冻结匹配函数；新代码只校验来源并汇总集合变化。

## 范围与工作点

- 两个已登记开发片段：DJI_0026_2、DJI_0067_2，各 160 帧、512×640；4 个确认来源不读取。
- 严格小目标集合固定为 5,200 个目标帧、130 条轨迹、2 个片段。计算匹配竞争与未匹配组件时沿用全部有效标注，不能仅使用小目标标注。
- 阈值固定为 `probability >= 0.5`；8 连通组件及组件峰点、一对一框匹配、像素坐标和歧义处理全部沿用旧函数。U 是未匹配组件数，不是官方 Fa 或已经确认的误检数。
- O 起点为 `[0,36,72,108,120]`；S 起点为 `[0,24,60,96,120]`。窗口长度均 40，原预处理、sigmoid / 插值次序和逐像素 max 融合不变。8 个唯一窗口可复用，但每套安排仍是整段视频 5 窗；不按目标或帧选窗。
- pooled U 预算为 4,015，分别判断 O 与 S，不汇总成十窗模型。不根据结果改变阈值、安排、训练终点或候选定义。

## 输入缓存接口

每个条件 `N0/N1/N2` 和片段的路径为 `predictions/<condition>/<sequence>/`。

| 文件 | 必要内容 |
|---|---|
| `windows/window_<start:03d>.npz` | `probabilities`: float32 `[40,512,640]`、有限且为概率；`start`、`end=start+40`；8 个唯一起点完整 |
| `official_fused.npz` | `probabilities`: float32 `[160,512,640]`，必须逐元素等于 O 的逐像素 max |
| `COMPLETE.json` | 完成状态、条件/片段、原始数据 hash、各窗口 hash、O 融合 hash；以及固定协议、权重、训练与推理源码身份 |

评估先核对固定 512 步检查点与冻结发布骨干的身份，再调用原 scorer。不存在检查点筛选。缓存源 hash、旧 scorer hash、匹配辅助函数和标注 hash 均写入评分 receipt。

## 冻结分层与比较

直接读取 `../low_response_information_20261011/COHORTS.csv`，不根据新模型结果修改分组：全窗低于 0.5 共 4,342，极低响应子集 4,170，O/S 原双侧成功 646，额外窗口可恢复 104。全量对象都进入逐目标表。

主机制比较为 N2 对 N1，其次 N2 对 N0；三者均对相同安排下的发布权重比较。每个比较都报告真正的新增、丢失、共同匹配和共同漏检集合，不能把恢复总量或匹配净变化当作结构独有贡献。N0 保留原骨干的时序特征，不称为单帧模型。

背景同时报告 U、框外前景像素、全部组件与未匹配组件面积及分位数。框外区域严格继承旧评价的有效标注框排除规则，不临时更换掩码。S 的原 U 为 3,967；落在 4,015 内仍不等于相对 S 背景成本不增加。

## 固定交付表

- `OBJECT_COMPARISON.csv`：10,400 行，每个目标帧 × O/S 一行，包含发布权重和 N0/N1/N2 的实际匹配、框峰响应、成功峰坐标、组件面积以及各比较集合标记。
- `SUMMARY.csv` 与 `SEQUENCE_SUMMARY.csv`：匹配、实际增损、冻结分层恢复及轨迹/来源数、背景量；pooled 与逐片分别报告。
- `COHORT_TRANSITIONS.csv`：各冻结分组的真实集合划分，保留 N2 对 N1/N0 的新增与重新丢失。
- `WINDOW_DEPENDENCE.csv`：O/S 双侧成功、仅 O、仅 S、双侧失败。646 保护集合分别给出单安排保持与双侧保持，二者不混用。
- `TRACK_SUMMARY.csv`、`RECOVERY_CONCENTRATION.csv`：逐轨迹恢复/丢失及前 1 / 前 5 轨迹贡献，避免只给总体数量。
- `CONTINUOUS_MISS_TRACKS.csv`、`CONTINUOUS_MISS_SUMMARY.csv`、`RELEASE_MISS_SEGMENTS.csv`：原观察范围内的连续漏检、变化方向和冻结发布漏检段内的恢复。
- `FRAME_COUNTS.csv`、`component_areas.npz`：完整背景/组件核验明细。

连续段要求局部帧号与来源帧号均恰好加 1；缺标、帧号中断和原筛选空缺打断连续段。分组过滤后的连续性单独计算，不能解释成完整物理轨迹长度。最长漏检汇总同时报告目标帧、轨迹和片段数。

## 判定边界

沿用用户工单：N0 解释收益则不主张显式时序证据；N1 有效而 N2 无独立优势则停止局部参照主张；N2 仅压低背景与目标且没有更好取舍则不通过；只有预算内恢复、保持代价可接受且优于两个简化控制时，才考虑后续成对重复和新来源验证。不能新增“恢复若干帧即通过”的数值门槛。降低 U 不独自等于整体背景改善。

本轮属于固定种子 46、固定预算的开发筛选，不能主张多种子稳定、独立来源泛化、官方 Pd/Fa 提升或方法新颖性已经确立。

## 核验

`--baseline-check` 只读取已完成发布结果，验证 O 为 M=700 / U=4,015 / 框外前景=38,368，S 为 M=720 / U=3,967 / 框外前景=38,641；不启动模型推理。独立 stdlib `validate_tables.py` 从对象与帧明细重新计算总数、真实集合、连续段和源 hash。它是表格独立复算，不声称重新推理或完整原始分数图独立评分。
