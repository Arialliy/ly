# 近期方法的共同目标级对照协议 v1

日期：2026-10-11。状态：已写明协议，尚未产生 CHAL 检测结果。此协议不修改既有 DeepPro-Plus 结果，不将不同模型的分数视作同一概率量。

## 1. 先完成原生设置验证

首选 CHAL 的 NUDT-MIRSDT 设置：完整作者模型与该权重对应配置、作者 COCO 框标注及测试划分、原生五帧预处理、原生框后处理、原生 COCO AP。选择它是因为当前已有同名公开数据的图像材料；**DeepPro 的分割版不是已经核对过的 CHAL 框检测版**，不能自行从 mask 造框后称原生复现。

先严格载入全部模型参数，再在官方列表按确定顺序选第一条完整序列验证图像、帧号、框坐标、批处理和后处理；这只证明工程流程。随后在该权重对应的完整官方测试划分上运行一次原生评价，逐项比对作者报告的设置与指标。若缺权重的对应指标、划分或输入规则，标记“无法核对作者成绩”，不凭一次前向认定复现可信。若完整测试差异无法解释，停止向开发材料迁移，不能将其差距解释为模型局限。

选择一个作者预定检查点，禁止根据测试结果尝试多个模型并挑最高分。修复缺文件、训练器或评价器须独立列补丁和行为差异；若无法恢复作者实现，只能另称“本地重实现”，不能替代上述原生验证。

当前资产门槛见 [CHAL_FEASIBILITY.md](CHAL_FEASIBILITY.md) 与 [ASSET_PREFLIGHT.json](ASSET_PREFLIGHT.json)。本轮未通过，故未运行 CHAL 原生验证或开发集推理。

## 2. 数据角色和统计单位

沿用 [DATA_SELECTION.json](../stage1_goal/DATA_SELECTION.json) 的角色。DJI_0026_2 / DJI_0067_2 是已经反复使用的开发／校准片段，各160帧；本轮已从旧表重建 [FROZEN_OBJECT_COHORT.csv](FROZEN_OBJECT_COHORT.csv)，5200目标帧、130轨迹、2片段。4342全窗口低响应、4170极低响应、646两安排均成功、104额外窗口可恢复的成员不随新模型重新定义。[COHORT_CHECK.json](COHORT_CHECK.json) 记录输入与输出哈希及逐项数量核验。

这些分层是 **DeepPro-Plus 输出定义的困难集合**，会偏向暴露它的失败；主表必须同时报告全部5200对象，不能只用4342子集给方法排名。重复帧不当独立样本，分别报片段、轨迹、目标帧数量，不在2个来源上宣称总体显著性。

四个既定确认片段 DJI_0051_3 / DJI_0075_3 / DJI_0139_2 / DJI_0343_3 不用于阈值、检查点或适配选择。本轮不读取其模型结果。若后续进入确认阶段，应先再次核查它们是否仍未产生/查看结果，再冻结配置、一次运行。原划分按源视频前缀隔离，不等于地理场景独立。新模型训练来源还须单独核查，不能沿用 DeepPro 的训练交集结论。

## 3. 保留原生任务，另设共同定位诊断

| 输出 | 原生评价保留 | 共同定位候选 |
|---|---|---|
| DeepPro-Plus 密集图 | 有原生标注时报告其原生 Pd/Fa；本开发集继续报告旧 M/U/框外前景 | 旧规则下的8连通组件峰：最高概率、平局取行优先，像素中心坐标 |
| CHAL 检测框 | 原生 COCO AP/AP50、明确工作点下框Precision/Recall；保留NMS和置信度定义 | 原生NMS之后每个框的几何中心，一个框产生一个候选；分数采用作者 objectness×class confidence |
| TEP-SAM 分割图（仅后续需要时） | 分别注明论文指标公式、实际官方评价器、必要修订；不得混写Fa | 保留作者 sigmoid→尺寸恢复顺序，再用共同组件峰规则；不是重新训练或改输出阈值顺序 |

共同任务是“定位点是否进入一个标注框”，不是精确质心回归。CHAL预测框中心是一种输出约定，不是把GT框中心当精确质心。须额外保留 CHAL IoU≥0.5 的实际框匹配结果；如果中心诊断改善而框定位严重不合格，只能称中心诊断改善。

坐标统一到原始640×512连续像素坐标，完整记录 resize/letterbox 的逆变换；图像像素中心为 (x+0.5,y+0.5)。GT用原始半开区间 [x,x+w)×[y,y+h)，不扩框、不放宽边界。所有有效标注对象先参与一对一匹配，然后才统计严格小目标；不能将其他已标目标计入背景。GT有效性与原 `analysis/analyze.py:prepare_gt` 保持一致，按原实现排除 ignore，不因 iscrowd 单独排除；涉及 ignored 区域的候选另外标记，不在回放时新增忽略规则；COCO 原生 ignore/crowd 独立处理；未匹配候选不能自动叫作已确认误检。

匹配沿用原 `match_frame` 的最大基数增广路：GT按(track_id, annotation_id)固定排序，各GT的候选边先按框尺寸归一的中心距离、降序候选分数、候选ID排序。旧组件ID与旧实现一致，框候选ID按恢复后坐标和原预测索引确定。报告多GT竞争与平局数量，不为某个方法另选有利匹配。

共同量另命名：M_loc（严格小目标匹配）、G_loc/L_loc（相对同一固定DeepPro安排）、Q_loc（全有效GT匹配后未匹配的定位候选数）、Q_loc/帧。**Q_loc 是统一定位接口的未匹配候选数；不是原生框FP、不是论文Fa，也不是跨方法相同的像素背景成本。** 对旧DeepPro固定输出可与旧U数值一致，但不能因此把CHAL未匹配框直接填入旧U列。

另报每种输出自身的背景负担：DeepPro/TEP的框外前景、组件面积；CHAL按原生IoU≥0.5匹配的未匹配框数、框面积和重复检测。框面积与像素前景面积不作同单位质量排名。保留原始输出，以检查数量下降是否来自输出合并或候选截断。

## 4. 分数和工作点

旧 DeepPro-Plus O/S 主结果始终固定0.5。CHAL的0.5分数不与它等价。这里作者默认指 test.py（候选下限0.001、NMS IoU0.65），不是 predict.py（0.2、0.3）；权重对应配置尚待核实。COCO maxDets=100只属于原生评价，不能无说明截断共同诊断候选。CHAL原生测试置信度、NMS、最大输出数等先按权重对应配置冻结；原生AP按原定义报告。

共同定位工作点先报告作者默认设置，再在两个已有开发片段上绘制完整可用的定位召回—Q_loc/帧曲线，标明低分候选截断造成的可见范围。若需要一个预算工作点，使用发布 DeepPro-S @0.5 经过同一共同接口得到的 Q_loc/帧作预算；按“满足预算时最大开发集M_loc，平局先较低Q_loc再较高阈值”的预先规则选CHAL阈值。它是**开发集校准结果**，不是独立改善证明；同一阈值固定应用于所有片段，禁止逐帧/逐目标选择。

旧4015预算保留为旧协议；不把它自动当作CHAL原生框FP预算。若共同接口确实完全保留旧 GT/匹配，S参照对应3967/320=12.396875定位候选/帧；实际执行时必须先回放证实，再使用该值。不得凭预期数值跳过接口校验。

本轮尚未实现或运行上述共同评分器，协议不能冒充已验证代码。后续评分器必须用原S完整回放确认720匹配与3967候选，并用重复框、非小目标、边界点和坐标逆变换检查后再产生新结果。组件阈值变化会改变连通性，不能用只对固定组件分数排序替代重提组件。

## 5. 时间访问和总成本

| 方法 | 每次实际输入/输出 | 160帧片段所需工作 | 信息条件 |
|---|---|---|---|
| 当前DeepPro-Plus O/S | 40帧→40帧响应；五窗max融合 | 每安排5个40帧时间窗，每窗再含既定空间平铺；共200帧曝光 | 离线；当前帧可使用窗口内未来帧 |
| CHAL | 前4帧+当前帧→当前帧框 | 原生逐帧输出需要160个五帧调用，共800帧曝光（未经缓存）；首部按作者规则复制 | 历史访问；不能把5帧输入误写成整段只跑5窗 |
| TEP-SAM（未运行） | 当前帧±3→中心帧分割；1024²输入 | 160个七帧调用，共1120帧曝光（未经缓存）；边界复制 | 使用未来3帧；SAM编码成本需计入 |

帧曝光不是FLOPs或时间的等价单位；当前DeepPro空间平铺次数、CHAL原生分辨率与缓存、TEP-SAM编码器均影响实际成本。后续记录同硬件的总片段耗时、预处理/模型/后处理分项、峰值显存、分辨率、实际前向数、精度、缓存和冷启动。不能用不同论文报告的FPS证明同预算。

本轮选择比较各模型原生运行方式下的离线系统表现，允许看到同一160帧片段，明确各自实际访问子集；**不宣称严格相同时间信息或计算预算**。只用完整历史/未来的内区间另列边界敏感性结果，同时仍保留全5200对象主表。不能把DeepPro改成5帧后仍叫同一个发布基线。

## 6. 能够与不能够下的结论

原生验证通过后，CHAL在现有开发片段的直接迁移只能先回答“这个发布模型在这些来源能否改善”；若其训练来源与DeepPro不同，差距不能全部归因于架构。迁移失败也可能是域差异，不足以宣布近期方法共同失效。

若需比较架构与监督机制，应另设相同源级训练/开发划分、标注信息量、更新预算的适配实验；这不是本轮已经完成的内容。新结构只在近期对照仍有稳定缺口、并找到缺失信息或约束时设计。若CHAL已解决主要失败，接受它作为强基线；若只有代码修复收益，归为复现修复。

最终逐对象表需保留：身份与冻结分层、各原生输出/坐标/分数、时间范围与边界状态、原生匹配与共同匹配、G/L/Q、片段与轨迹汇总、检查点/配置/数据哈希。没有CHAL输出的字段保持缺失，不能用0代替“尚未运行”。
