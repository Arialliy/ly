# DeepPro-Plus 真实序列逐帧诊断：独立协议审阅

日期：2026-10-10（Asia/Shanghai）。本审阅只读代码、标注和已有复现报告，没有运行检测器、下载数据或读取本轮预测结果。它给出诊断定义与解释边界，不认定任何失败已经发生。实际冻结协议和指标实现由主执行者另行保存。

## 1. 本轮对象及证据层级

- 模型：固定官方 RGB-T DeepPro-Plus 权重和 checkpoint 邻接模型源码；本地 seed=46，其他数值设置沿用已记录推理环境。46 是源码函数默认值，本地显式启用；作者权重训练 seed 未知。
- 官方 NUDT-MIRSDT 全测试集的权重推理已在报告精度下复现；这支持实现可执行和该基准口径正确，不直接保证当前真实视频域上的性能。
- 当前片段：VT-Tiny-MOT `DJI_0028_2/01`，原帧173–332，共160帧，640×512、15 fps；依据标注轨迹预选，未依据预测筛选。
- 原标注共1,280项，8条轨迹各160项，均 `ignore=0, iscrowd=0`。选中轨迹为3800006。它是额外开发片段，不能称独立测试集；序列名不在DeepPro公布划分中不等于拍摄场景独立。

## 2. 建议冻结的点响应诊断

### 2.1 从概率图到唯一候选

对每帧融合概率图分别在预定阈值 **0.1、0.5、0.9** 计算，不使用标签选择最佳阈值。明确采用 `p >= threshold`，若实现选择严格大于则在协议中写清，保持所有结果一致。

1. 阈值掩码作8连通组件标记；每个组件拥有帧内唯一ID。
2. 组件内最高概率像素作为代表点，分数是该像素概率；最大值并列时按 `(y,x)` 字典序取首项。
3. 像素索引 `(x,y)` 可按像素中心 `(x+0.5,y+0.5)` 与COCO框 `[left,top,left+width,top+height)` 比较。必须预先固定这一坐标约定并全程使用。
4. 不在观察输出之后设面积过滤。保存组件面积、包围框、普通质心、概率加权质心、最大概率及最高点，以便识别大块响应、细碎响应或合并组件。
5. 对每一帧全部有效GT框同时建二部图：代表点在框内即允许匹配。使用最大基数一对一匹配；一组件最多匹配一目标，一目标最多匹配一组件。
6. 多个最大匹配时，固定规则，例如在最大基数约束下优先归一化中心距离小的边，再按GT id、组件id确定并列顺序。保存边和最终分配，以复算轨迹级身份。

报告名称建议 **“组件峰值点—标注框匹配率”** 或 **“标注目标点响应覆盖率”**。它是此开发片段的诊断指标，不等同于官方Pd、框AP或论文召回。前景分割点响应小于GT外接框很常见，不能直接用组件框IoU≥0.5判定一个点目标“未检出”。

### 2.2 必须保留的辅助量

- 每目标每帧：框内最大/均值概率、匹配组件ID、点偏移 `(dx/w,dy/h)`、匹配与否、连续未匹配段。
- 框内最大概率只是响应探针，允许背景尖峰、共享大组件、相邻目标等因素进入框内。不能把 `box_max >= threshold` 单独当作对象检出。
- 一个大组件若跨越两个目标，只能记一次匹配；同时记录组件是否与多个GT框相交，避免将合并掩盖为全部成功。
- 一个目标框里有多组件，只匹配一个，其余记为“框内未分配组件”，可作为重复/碎片化诊断，不能立即认定多个真实假目标。
- 全图“框外组件”“有匹配边但未分配组件”“无匹配边组件”分别计数。后两者可能因匹配竞争、代表点偏移、标注遗漏而产生，统一称 **未匹配响应**；未经原图人工核查不写成已确认误报。
- 保存GT框外阈值像素数/比例、组件面积分布；这些是标注框之外的响应负担，不是官方FalseNum/Fa。
- 若最高峰点在框外而组件与框相交，单列该情形。可辅助计算质心在框内的结果，但不能事后用其中更好的定义替换主指标。

注意：组件数量随阈值和窗口最大融合可能合并或分裂，因此组件匹配数不必随着阈值降低单调上升。最大融合只保证每像素概率不低于任一组成窗口，不能据此推断对象匹配数量必增。

|---|---|---|

| B2 | 253–292 | [80,120) |

**这些块不是官方推理窗口。** `runtime/infer_checkpoint.py` 依照原测试规则使用：

| 推理窗口 | 本地帧 | 原始帧（两端包含） |
|---|---|---|
| W0 | [0,40) | 173–212 |
| W1 | [36,76) | 209–248 |
| W2 | [72,112) | 245–284 |
| W3 | [108,148) | 281–320 |
| W4 | [120,160) | 293–332 |

融合为逐像素最大值。双覆盖本地范围为 `[36,40)、[72,76)、[108,112)、[120,148)`，共40帧；其他120帧单覆盖。B3中有28/40帧双覆盖，B0为4/40、B1为4/40、B2为4/40。因此后段改善可能同时包含窗口上下文和融合机会差异，不能直接归因为速度变化。

每帧输出记录：原始帧ID、本地帧、所有覆盖窗口ID、每个窗口中的slot、覆盖次数，以及融合前各窗口响应。若只保留max结果，会丢失定位窗口原因最有价值的信息。

逐轨迹及每块报告：匹配帧数/有效标注帧数、最长连续未匹配长度、未匹配段起止、进入/离开匹配状态次数、响应分位数、点偏移分位数。0.1/0.5/0.9全部给出，0.5作为预设主视图。160帧存在强时间相关性，不做把1,280个框视为独立样本的显著性检验；单片段阶段主要描述现象。

**零额外干预的第一项时序核查：** 对天然重叠的同一真实帧，比较两个原始窗口的组件/分数/点偏移。若同一图像标签下结果差异明显，说明上下文或窗口位置影响响应；仍不能单凭这一比较区分“上下文内容”与“slot权重”。

## 4. 从源码可以确认什么

源码版本：`8fa1a68b94eb22e94ccd0529e6c5ceccdaa7ec28`。

- `official_deeppro/networks/layers/TPro.py:18–36`：8个 `Linear(seqlen,out_len)`，本权重均为40→40。每个头在固定空间坐标对时间槽作线性混合，权重不是随输入重新生成的QK注意力。不能因变量名QK而写成内容自适应attention。
- TPro无因果掩码；输出一个时间槽能使用窗口内的过去和未来。推理是离线40帧块，不是逐帧在线检测。无跨窗口持久隐藏状态，窗口max只是后处理；这本身不构成原任务中的缺陷。
- 40×40稠密权重没有结构性时间平移等变约束，所以相同真实帧位于不同slot时可能受不同权重与上下文影响。是否导致可观测失败必须实测，不能由结构直接断言。
- `STD_Resblock` 的TD卷积在时间维dilation=2，SD卷积空间dilation=2；两块有残差通路。Plus还具有输入空间差分卷积，因此不能由“纯时间差分消去常量信号”推出Plus必然漏静止目标。
- `SDifferenceConv` 应按实际有效卷积核分析，不能直接当成教科书的严格零和拉普拉斯：实现把中心置为包含原中心在内的空间权重和，空间有效权重总和不必为零。
- Plus空间支持半径为9像素：输入7×7贡献3，每个STD块贡献1+2，两块共6。TPro只沿时间混合，不额外扩大空间支持。因此不存在显式沿轨迹/光流的远距离对应模块；但不能把目标跨帧位移超过9像素直接当成漏检定理，当前帧局部特征仍可响应。
- `runtime/infer_checkpoint.py` 以eval、FP32、固定归一化和严格state_dict加载运行，空间tiling是执行适配。若使用tiling，应保留已有完整/分块数值一致性见证；不要把分块接缝误写成时间现象。

这些是 **机制检查入口**，尚未证明它们是性能瓶颈，也没有宣布一个论文创新点。

## 5. 避免把运动相关性误写成原因

每个时间块并列报告框面积/宽高、可见性核查、局部目标—背景对比度代理、背景纹理和配准质量；配准必须排除目标框区域，并给有效点数/残差等质量量。背景估计不可靠时标成未知，不强行补偿后声称得到物理运动。

仅同一目标从早到晚更快且漏检更多，仍与时间、位置、对比度、运动模糊、局部背景、窗口slot及覆盖次数混杂。原图均值/方差代理不能替代目标真实SNR。其他轨迹只提供同场景参照，尺寸、类别、背景差异未控制时不能作为直接因果对照。

低阈值可恢复匹配但带来大量未匹配组件，支持进一步看校准/真假区分，不能说已经解决。所有阈值都低响应也不能直接推出“时序抑制”；仍可能是视觉域、位置、局部低对比度或权重适用范围。

## 6. 只有观察成立后才做的最小干预

| 先观察到的稳定现象 | 最小下一步 | 能检验的范围 |
|---|---|---|
| 同一帧在天然重叠窗口出现明显响应/定位分歧 | 保留同一真实帧，按预设少量起点平移40帧窗口，报告所有合法起点和slot；先不改权重 | 窗口上下文/位置敏感性。起点平移同时改变上下文，仍未隔离slot本身 |
| 稳定连续未匹配段与背景移动同步，背景配准质量可靠 | 固定一次纯背景估计的几何补偿与原输入对照，预测映射回原坐标；报告插值/边界影响 | 相机运动补偿是否改变该错误，尚非通用新方法 |
| 窗口内局部目标响应存在，但融合前后对象匹配变化明显 | 只离线比较已保存窗口的max、单窗口输出及明确固定规则 | 融合/组件合并影响，不需要重新训练，也不代表替换规则已公平优越 |
| 跨0.1/0.5/0.9仅分数变化而定位点稳定 | 保存原图、组件及未匹配响应负担，扩至固定其他开发片段复核 | 分类置信度/阈值脆弱性，不能仅凭此归因于时序建模 |
| 各块/多阈值均表现稳定，选中轨迹无明显失败 | 如实记为该候选不支持缺陷，依原先候选队列继续核查 | 不重新挑阈值或改标签制造现象 |

不应同时开展这些干预。先由逐帧错误和窗口结果决定一项。新模块、单帧主对照、其他时序模型的大规模训练都不是本轮前置要求。找到可重复现象后，再查已有时序方法是否已覆盖具体缺口。
