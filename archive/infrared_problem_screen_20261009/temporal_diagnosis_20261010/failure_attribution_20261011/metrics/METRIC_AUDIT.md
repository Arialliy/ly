# 官方指标、代理命中与背景结构核查

2026-10-11。范围：已用开发片段 DJI_0026_2、DJI_0067_2，320 帧，16,297 个有效标注目标帧，其中 5,200 个满足既定几何小目标规则。原发布权重缓存，固定 `>=0.5`，原五窗 max 与对称五窗 max。没有训练、模型前向或新确认材料。

**结论：5 个“原窗点匹配、融合失配”例都仍保留框内前景和中心邻域命中，不能据这些例子宣称官方 Pd 下降。对称安排的 74/54 点匹配交换也包含两种变化：70 个新增和 47 个丢失确实对应框内阈值命中出现/消失，其余并非框内响应消失。未匹配组件降低不等于背景像素降低。**

## 1. 当前官方实现究竟评估什么

核查本地提交 `8fa1a68b94eb22e94ccd0529e6c5ceccdaa7ec28`，工作树干净；从作者 GitHub 下载该**固定提交**的四个文件，与本地逐字节相同。见 [SOURCE_AUDIT.json](SOURCE_AUDIT.json)。未以当前 main 分支替代本地版本。

| 环节 | 固定提交中的实际行为 | 与本轮点匹配的差别 |
|---|---|---|
| 时间融合 | `test.py` 对重叠时刻 sigmoid 概率取 `torch.maximum` | 像素分数不会被融合降低；本轮原融合缓存也已按五窗 max 核验 |
| 阈值 | ShootingRules 使用 `>= DetectTh`；IoU 另用 `> threshold_eval` | 本轮点匹配和代理均固定 `>=0.5`，不是 IoU 的严格大于 |
| 标签对象 | 对传入 target map 作 8 连通标记，每个标签连通区域算一个目标 | 不是逐 bbox / track 对象；相邻标签可成为同一对象 |
| 命中 | 对每个标签区域中每个像素检查 ±1 的 3×3 邻域，任一前景即可命中该区域 | 不抽预测组件峰、不要求峰在框、不做预测与标签一对一分配；一个前景可能命中多个标签区域 |
| 背景分子 | 排除全部标签像素 ±4 的 9×9 邻域后，统计剩余预测前景像素 | 不是未匹配组件数，也不是 bbox 框外像素 |
| 背景分母 | `writeMIRST_ROC` 以全部测试图像像素数归一化 | 不是背景域面积或帧数 |

源代码：[ShootingRules.py 固定提交](https://github.com/TinaLRJ/DeepPro/blob/8fa1a68b94eb22e94ccd0529e6c5ceccdaa7ec28/ShootingRules.py)、[test.py 固定提交](https://github.com/TinaLRJ/DeepPro/blob/8fa1a68b94eb22e94ccd0529e6c5ceccdaa7ec28/test.py)、[write_results.py 固定提交](https://github.com/TinaLRJ/DeepPro/blob/8fa1a68b94eb22e94ccd0529e6c5ceccdaa7ec28/write_results.py)。

需要特别纠正“centroid 就是 bbox 中心”的理解：**RGB-T 分支读 `segmentations/<sequence>/` 图像，将非零值置 1，然后直接令 `centroid=label`。只有 NUDT-MIRSDT 分支另读 `masks_centroid`。** 因而 RGB-T 的命中区域取决于输入 mask 支持域，源码不能证明它等于中心点或公开矩形 segmentation。[数据加载器固定提交](https://github.com/TinaLRJ/DeepPro/blob/8fa1a68b94eb22e94ccd0529e6c5ceccdaa7ec28/data_utils/TestDataLoader.py)

论文 IV-F 明确说**训练**由 bbox 生成粗 Gaussian 标签，但并未在这段文字中给出我们可复现的测试 mask 支持域。当前本地作者数据目录只有 split 列表，本轮材料只有公开原图和 bbox 标注，未获得作者实际评估用 segmentations 图像。因此不能把公开 bbox 的矩形 polygon 当成作者 mask，更不能把本次代理数字写成官方 Pd/Fa。[论文 v5，IV-F](https://arxiv.org/html/2506.12766v5#S4.SS6)

坐标边界也需保留：官方函数在 ±1/±4 邻域切片前没有截断负下标；左/上边缘可能产生空切片。本文独立 bbox 中心代理显式截边，另有“合成中心 map + 原函数”适配保留源码语义。两段材料两种安排中，截边与原切片的**背景像素计数差为 0**，不据此声称所有数据都没有边界影响。`test.py` 在输出宽与标签宽不同时用 OpenCV resize 对齐；本轮双方都是 512×640，无此缩放。

## 2. max 对固定邻域命中确有单调性

设固定对象区域为 R、固定阈值为 τ，命中定义为 R 内存在分数 ≥τ 的像素。则

`H_R(max_w p_w) = max_w H_R(p_w)`。

这适用于固定标签的官方邻域命中以及本轮冻结的中心/框内代理。标签、对齐和阈值须保持相同。组件峰值与一对一匹配会随新增像素、连通形状和峰位置改变，不满足这一恒等式。

数值核验原五窗到原融合：检查 **131,072,000 个像素比较**，没有 `fused < window`；对 16,297 个有效对象的两个固定区域代理，any 原五窗命中与融合命中完全相等。原 5 例情况如下。

| 序列 | 源帧 | 轨迹 ID | 原融合点匹配 | 原融合中心代理 | 原融合框内像素命中 |
|---|---:|---:|---:|---:|---:|
| DJI_0026_2 | 147 | 400005 | 0 | 1 | 1 |
| DJI_0067_2 | 74 | 7701908 | 0 | 1 | 1 |
| DJI_0067_2 | 75 | 7701908 | 0 | 1 | 1 |
| DJI_0067_2 | 142 | 7701917 | 0 | 1 | 1 |
| DJI_0067_2 | 144 | 7701917 | 0 | 1 | 1 |

5 例的中心邻域最高概率均 ≥0.99987；它们不是融合把目标响应抹掉的例子。其是否构成所需定位输出的损失，应由明确的检测输出规格判断，不能自动转成作者官方漏检。数据见 [FIVE_CASE_WINDOW_PROXY.csv](FIVE_CASE_WINDOW_PROXY.csv)、[FIVE_CASE_FUSION_PROXY.csv](FIVE_CASE_FUSION_PROXY.csv)、[MAX_MONOTONICITY_CHECK.csv](MAX_MONOTONICITY_CHECK.csv)。

## 3. 换安排带来的命中交换在代理中仍存在，但对象和幅度不同

[ADAPTED_METRIC_PROTOCOL.md](ADAPTED_METRIC_PROTOCOL.md) 在计算前冻结：[PROTOCOL_FREEZE.json](PROTOCOL_FREEZE.json)。中心为 `floor(bbox center)` 所在像素、命中用截边的 ±1 邻域、背景排除用截边的 ±4 邻域；所有 annotation 独立计数。它对框中心误差敏感，因此同时报告框内任意像素命中，不筛选更好看的定义。

| 5,200 个小目标帧上的定义 | 原五窗 | 对称五窗 | 新增 | 丢失 |
|---|---:|---:|---:|---:|
| 原冻结点匹配 | 700 | 720 | 74 | 54 |
| bbox 中心邻域命中代理 | 625 | 642 | 67 | 50 |
| 框内任意前景像素命中 | 745 | 771 | 79 | 53 |

在**原点匹配的 74 个新增对象**内，70 个框内命中从 0→1，4 个原本已有框内前景；中心代理则为 51 个 0→1、1 个两边命中、22 个两边均未命中。

在**原点匹配的 54 个丢失对象**内，47 个框内命中从 1→0，7 个仍有框内前景；中心代理为 24 个 1→0、3 个两边命中、26 个两边均未命中，另 1 个反而从中心未命中→命中。这说明“响应不足”和“峰值/匹配输出变化”应分开，而非把 54 个统称响应塌缩。两安排共同点匹配成功的 646 个对象中，中心代理仍有 8 新增、23 丢失，也显示两个指标不能互换。

直接调用原 ShootingRules、输入**合成中心 map**的 640 个帧次，与独立实现逐帧输出完全一致；但 16,297 个 annotations 在合成 map 中成为 15,782 个标签区域：84 次中心像素重合、431 次由邻接导致的额外区域合并。因此合成 map 的 TrueNum 为 1,769→1,810，不等于逐 annotation 中心代理的 1,791→1,823。此适配仅核验实现，不用作官方成绩。逐对象结果见 [OBJECT_METRICS.csv](OBJECT_METRICS.csv)，交换表见 [POINT_GROUP_METRIC_EXCHANGES.csv](POINT_GROUP_METRIC_EXCHANGES.csv)。

## 4. 背景并未在所有定义下改善

| 320 帧总体量，固定 0.5 | 原五窗 | 对称五窗 | 变化 |
|---|---:|---:|---:|
| 所有 8 连通组件 | 7,276 | 7,339 | +63 |
| 点匹配成功组件 | 3,261 | 3,372 | +111 |
| 未匹配组件 | 4,015 | 3,967 | −48 |
| 总前景像素 | 98,381 | 99,357 | +976 |
| 全部有效 bbox 框外前景像素 | 38,368 | 38,641 | +273 |
| bbox 中心 ±4 排除域外前景代理 | 59,922 | 59,981 | +59 |
| 未匹配组件的总面积 | 45,232 | 45,136 | −96 |
| 未匹配组件中的框外像素 | 36,169 | 36,478 | +309 |

**实际是总组件增加、匹配组件增加更多，所以未匹配组件减少；不是总组件变少。** 未匹配组件本身也不是人工核实的背景误警，其中有候选峰落在标注框内但未获得一对一分配的组件（1,003→1,024）。

未匹配组件面积中位数均为 4，平均面积 **11.266→11.378**，75 分位 **15.5→16**，95 分位 **41→45**，99 分位 **63→65**，最大值均 341。可描述尾部有所变化，不能仅凭总体分布认定某次组件合并造成变化。两安排所有组件的平均面积为 13.521→13.538。

按序列背景计数：0026_2 的未匹配组件 741→707、框外像素 15,254→15,272、中心背景代理 16,708→16,671；0067_2 分别 3,274→3,260、23,114→23,369、43,214→43,310。

上一轮“相同背景预算”只能指**当时冻结的未匹配组件预算**。在本次两个固定像素口径下，对称安排总体均略高于原安排；不能据组件预算通过就声称“相同官方 Fa 下改善”。逐帧/总体量见 [FRAME_METRICS.csv](FRAME_METRICS.csv)、[TOTALS.csv](TOTALS.csv)，组件面积见 [COMPONENTS.csv](COMPONENTS.csv)、[COMPONENT_AREA_SUMMARY.csv](COMPONENT_AREA_SUMMARY.csv)。

## 5. 对研究路线的含义与边界

本轮没有否定时序安排导致实际响应差异：74/54 点匹配交换中，大部分伴随框内阈值命中出现/消失。但 **5 个原 max 后点匹配丢失例首先是所用峰值输出规格下的失败**，不能作为官方邻域命中下降证据。它们需要进入输出提取环节审计，而不是优先用新模型提高已有接近 1 的框内响应。

当前可继续分离：成功窗口被移除造成的覆盖/位置/内容变化，以及保有框内前景却没有合格峰值输出的情况。复杂建模前，应先明确所需输出和主评价定义，获得作者实际评估标签或明确采用公开 bbox 检测协议。本文代理没有解决该标签缺口，也没有建立独立测试增益。

执行：[compute_metrics.py](compute_metrics.py)、[verify_raw.py](verify_raw.py)、[RUNTIME.json](RUNTIME.json)、[container.log](container.log)、[SUMMARY.json](SUMMARY.json)。额外原始数组复核使用 OpenCV 8 连通标记与显式像素中心不等式栅格化，独立于原匹配辅助函数；结果见 [RAW_VERIFICATION.json](RAW_VERIFICATION.json)。
