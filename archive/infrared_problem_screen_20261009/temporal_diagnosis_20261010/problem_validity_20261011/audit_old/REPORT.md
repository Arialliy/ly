# 原四片段：逐窗口点匹配—官方融合点匹配独立复核

日期：2026-10-11。仅使用原发布权重已保存的 CSV，主阈值固定 0.5。没有新训练、GPU 推理、阈值搜索或新方法。独立脚本 `audit.py` 从逐窗口与融合逐对象记录重新聚合，未读取旧汇总数字作为结果。

## 结论

**原四片段确有最终融合未匹配、某个已测窗口已匹配的目标帧，但绝大多数需要额外窗口；原 97 个强响应翻转例中，没有一个属于“原官方五窗口已经匹配、融合却丢失”。** 这支持继续检查窗口安排的实际代价，但没有建立固定信息、计算和背景预算下的可部署收益。

旧 1,417 队列中，43 个目标帧属于“任一已测窗口匹配而最终融合不匹配”，其中 5 个原官方窗口已经匹配，38 个仅额外窗口匹配。5 个全部来自一条船只标注轨迹，最终融合框内最大概率均为 1.0，且全部不在原 97 强翻转队列中。因此不能把这 5 个点匹配损失称为融合造成的响应塌缩，也不能将 43 个当作同预算下可恢复的检测量。

## 匹配定义与对齐

- 点匹配沿用原诊断器：概率阈值、8 连通组件、组件最高概率点位于原框内、一对一匹配。它不是官方 Pd/Fa。
- 官方融合记录来自 `analysis/<sequence>/per_track_frame.csv`；11 个窗口记录来自 `window_offset_experiment/analysis/<sequence>/per_context_all_tracks.csv`。
- 官方窗口起点为 0、36、72、108、120；全集为 0 至 120、步长 12。额外六窗口起点为 12、24、48、60、84、96。
- 主连接键是 `sequence/local_frame/annotation_id`，逐行核对 source frame、原 image ID、track ID、框坐标与原始标注，检查实际可用窗口、slot、window_source。所有检查通过。
- 原 1,417 和 97 队列由逐记录重新构造，并与历史工件逐键一致。全部输入读取前后 SHA-256 一致。

“任一窗口匹配”是用真值事后识别窗口输出的诊断集合。它不是一个同时达到这些匹配的预测系统，不带可部署选择器，也不满足官方五窗口的计算预算。

## 原 97 例需要怎样表述

- 60/97 最终融合已匹配，不计最终漏检。
- 19/97 最终融合未匹配、某个额外窗口匹配。这 19 例涉及 11 个处理后轨迹 ID、三个片段，属于窗口覆盖机会，尚不是同预算收益。
- 18/97 所有 11 个窗口都未匹配，即使某窗口框内概率 ≥0.9。它们全部在 DJI_0047_3。
- 原五窗中已有匹配而被最终融合丢失：0/97。

原 1,417 队列另有 47 个所有窗口均未匹配但某窗口框概率 ≥0.5，其中 41 个至少一个窗口 ≥0.9。提高框响应和恢复点匹配不是同一件事。

## 原五窗融合后的五个小目标损失

五例均为 `DJI_0028_2 / track_id=3800007`，source frame 为 293、296、298、300、302（local frame 120、123、125、127、129）。原官方窗口 108 或 120 至少有一路匹配成功；融合未匹配，但框最大概率均为 1.0，融合匹配歧义字段为 0。它们需要检查组件形态、峰值选择和原框边界，不能先归因于时序特征抑制。

逐目标记录及成功窗口的起点、峰值坐标、组件面积见 `objects.csv`；逐轨迹完整计数见 `by_cohort_track.csv`。原 1,417 队列额外窗机会最多的是 `DJI_0047_3 / 4500503`，9/38 个；前三个贡献 ID 共 17/38 个，仍存在集中性。

## 样本边界与可支持的判断

原始 `INSPECTION_QUEUE.json` 明确记录，候选未使用预测、分数、mask 或错误来选择；采用按标注运动与尺度规则通过的连续片段，按预定序列顺序取样。因此不能称原四片段按模型低响应挑选。但它们仍是运动候选便利样本，不能代表全数据集；后续已反复观察，不能再作为全新确认样本。

97 队列直接按响应极值筛选；1,417 队列按窗口匹配歧义过滤，本身含模型输出条件。新增 1,850 几何严格小目标层只以标签几何过滤，有助于看清这层差异，但不能消除片段选择、标注可见性未核验、轨迹相关性与场景重复问题。两个 DJI_0028 片段还可能来自相同拍摄场景。

当前可以确认：旧样本中存在“官方最终诊断点匹配没有保留全部单窗口匹配”的具体案例；更大量的机会来自官方原本没有计算的额外窗口。当前不能确认：这种代价在未看过的样本中普遍且足够大、来自有害上下文导致的响应塌缩，或能在相同时间访问/计算/背景预算下减少。下一项对照应优先采用只含原五窗口或同为五窗口的合法安排，并报告净增损与未匹配组件，而不是把任一 11 窗的真值选择当作方法结果。
