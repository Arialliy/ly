# C-readout-v3：代码修正与固定短训结果

已先完成代码检查和修正，再完成 D、N 各256步训练及两个开发序列的 O/S 评价。**本轮 D/N 未比已有 F 增加任何目标恢复，也未改善持续漏检。** 三者的全部逐对象匹配布尔相同；N 仅在 O 下少1个框外前景像素和1个未匹配域像素，不能据此认定目标—背景取舍获得有效改善。

## 代码检查与修改

正式接入为 [train_modules/readout_weighting.py](train_modules/readout_weighting.py)，原参考 ZIP 和提取源码未修改。保留原目标/背景 ROI、有效掩码、8帧段、重复曝光和固定8窗口归约，仅更改新增逐帧项的负权重。正项仍走旧 -logsigmoid(q_positive) 路径；原 C 检测、保持和同轨迹损失不变。

发现并修复参考 N 在极负等分数背景上的 FP32 抵消误差：例如8个 q=-100000 的理论单位权重，原参考得到0.969233，修正后为1。停止梯度的归一化及组合 log-weight 使用 float64，随后转回原损失类型；未增加 epsilon、裁剪或更改模型训练精度。详细复测见 [CODE_REVIEW.md](resources/CODE_REVIEW.md)。

验证结果：用户参考30项、本地接入37项测试全部通过；实际 DEIM 原函数全背景负分支的值/梯度对照通过；固定8个真实训练批次的 unit 与旧 F 损失等价、正梯度不变、负梯度等价检查通过。1,222段全部非退化，N 的实际负读出梯度总量比值为0.9999999856–1.0000000403。旧负梯度的比较通过 assert_close，但未独立保存其最大误差，不把自比较的0当作旧新精确误差证据。

最终[执行验证](VALIDATION.json) PASS：D/N 完整恢复同一 C2048 和28个 Adam 状态，256步输入/标签/辅助曝光逐步与F一致，前端和BN冻结，原可训练模块发生实际更新，所有新推理及评价收据完整。无新校准、阈值修改或中间检查点选择。GPU2用于预检，GPU0/1用于D/N训练，三张卡均参与新推理；F直接复用已通过审计的v2 FRAME。

## 持续性与保护

F/D/N在固定130轨上的最长漏检逐轨向量一致：平均15.861538/15.769231帧，最大160帧；彼此无任何轨迹缩短或延长。相对CONT也没有最长漏检改善。有检出轨46/47，有连续至少2帧检出轨33/31，孤立010为23/24，均相同。4,170个极低响应目标帧仍无恢复。

646保护集合三组均保留638个双安排成功对象，8个失去双成功，其中2个在两种安排都失去成功。上述损失已存在于F，本次D/N既未增加也未修复。相对release的连续漏检并非所有方向都差：O为1轨延长、0轨缩短；S为1轨延长、2轨缩短，但均为F已具备的结果。

## 有效更新与训练诊断

这不是 N 数学退化或训练未执行。固定C2048快照上，N对原F负q梯度的相对L1分配差异中位约0.516；总量匹配但负参数梯度L2中位为F的1.142倍。D在固定8批中7批大幅削弱负监督；8批预算求和后约为F的18.89%，主要由第7号计划批次贡献，不能把极小的逐批中位比称为总体比。

同一预检中，N的负分支参数梯度L2相对新增读出总梯度L2中位仅约4.79e-6、最大8.87e-4，表明这组被采样背景的新增读出信号很小。这不表示原C的所有背景监督都很小，也不证明采样或保持项是唯一原因。

已有固定8批训练诊断显示：共同unit-frame loss均值由C2048的6.232268下降到F/D/N的5.885809/5.885584/5.885793。F/D/N端点非常接近；相对C2048，目标和背景logits都升高，背景升得更多，logit margin在8批均下降；概率margin则7批上升，不能混称“区分度改善”。原keep/C均值略降，det/base均值略升，非逐批统一。原可训练模块都有参数变化，F/D/N末态不同。上述结果支持“更新发生但本次新增负权重未转化为额外恢复”；无法从观察日志分离保持项的因果作用。
