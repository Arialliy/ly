## 本轮判断

在预定的主工作点（平均每帧最多 1 个虚警），B−A 的检出增量由开发集的 +4 变为 −1；D−C 由 +2 变为 0。C 和 D 都检出 16 个，实际虚警分别为 9 个和 8 个。将上轮开发阈值直接带到新视频时，D 比 C 多检出 5 个，同时多产生 21 个虚警。D 在每帧 0.5、1、5 个虚警预算下的合并检出数均与 C 持平。本轮证据不支持把联合表示作为论文主贡献。按阶段设计，到此结束围绕该假设的模型扩展；完整结果可作为后续研究的对照。

用另一套局部峰提取与二分图最大匹配实现复算，五个模型、四种汇总范围、五个工作点的共 100 组检出数和虚警数均与主评价一致。[独立复算脚本](verify_counts.py)

## 复算步骤

本目录沿用上轮四个已训练的适配器和作者权重。复核在原始分辨率上为每个待测帧输出五张分数图。上轮目录通过容器只读挂载。可从本目录在授权的空闲 GPU 运行如下命令。

```bash
mkdir -p runs
python3 locked_protocol.py
./run_gpu.sh 1 infer_locked.py --parity
./run_gpu.sh 1 infer_locked.py
./run_gpu.sh 1 evaluate_locked.py
```

首次运行记录权重、数据和上轮指标的校验值，再次运行会核对它们。完整画面的五张分数图保存为 runs/predictions 下的单个 NPZ，成功写完后改名，可以按帧续跑。在三张卡上并行时将推理按 `--workers 3 --shard 0`、`1`、`2` 分配给不同设备。本次在训练与开发使用过的同一数据集上，以预先留出的文件来源检验模型。合格目标数是逐帧框数，船只来源里只有两艘带轨迹编号的船。
