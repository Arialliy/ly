# C-v2 短修订实测报告

已用 GPU0/1/2 完成同一 C2048 检查点的三组额外256步修订，主端点统一为2304。新增项已连接到原检测链，但本轮连续段约束没有带来额外严格小目标恢复或连续漏检改善。逐帧读出产生了小范围增量，证据限于同一轨迹的两帧，尚不支持扩大当前 GAP 配置做正式长训。

这是按用户要求完成的训练链核验及短修订方向实验。旧 C-v1 记录未改动，本报告不把256步结果当作收敛结论或整个时序学习方向的否定。

M的分母为5200个严格目标帧；M/U沿用原诊断定义。O/S是同一批对象的两种窗口安排，不能相加当作不同目标帧。详细同帧、逐轨、全部背景与非严格对象结果见[完整结果表](RESULT_TABLES.md)及[配对方向证据](evaluation/DIRECTION.json)。

GAP与CONT在O/S全部5200个严格目标帧上的匹配向量逐项一致，恢复、丢失、覆盖轨迹和最长漏检均相同。GAP相对CONT的U增加29/19，框外前景像素增加191/194，未匹配组件面积增加135/78；非严格对象匹配增加7/7。因此它改变了检测输出，但没有形成当前研究目标所需的额外严格小目标恢复。

FRAME相对CONT在O/S均得2、失0，其中低响应得1、失0。两种安排恢复的是同一条轨迹 `DJI_0067_2 / 7700538` 的同两帧（本地帧23/24），不能计为四个独立恢复；两个新增均不是定义内的010孤立检出，其中一个位于观测边界。U同时增加37/28，框外前景增加248/225；没有多轨持续漏检改善。相对GAP，FRAME多2个严格匹配、U多8/9，不能据此声称已经找到总体最优取舍。

三组130条轨迹的最长漏检向量完全相同，平均最长漏检为O 15.861538、S 15.769231帧；相对C2048，两种安排均有3条轨迹延长、0条缩短。三组双侧保护均为638/646：8个对象失去双侧成功，其中2个在两种安排均漏检。原C2048为639/646、两侧均漏检0个。新增读出并未修复这项续训损失。

本轮三个新分支都满足当前评价范围内的U≤4015，S的U也都低于发布模型3967；但三个分支的框外前景和未匹配面积都高于发布模型。不能用组件数通过预算替代“全部背景代价没有增加”，本轮不扩大GAP的理由也不是U预算失败。

训练链已核实的变化如下。三组完整恢复同一 C 权重及28组 Adam 参数状态，step2048→2304，学习率1e-5、seed46和256步输入/标签/辅助曝光一致。原检测、对比、保持损失及其系数和归约原样复用；14,593个原参数可训练，总参数仍70,913，前端及BN缓冲固定。推理只运行原DeepPro-Plus、sigmoid、O/S五窗融合、0.5阈值及原组件匹配。[协议](PROTOCOL.md)和[执行完整性验证](VALIDATION.json)记录了代码、权重和缓存哈希，最终验证为PASS。

直接复用用户提供的[风险核心](../../deeppro_c_v2_reference/temporal_risk.py)与[分段核心](../../deeppro_c_v2_reference/segments.py)，本地增加[实际logits读出适配](train_modules/temporal_risk.py)和[训练分段适配](train_modules/segments.py)。在原框内取平均logit，背景取两个合法背景ROI均值的较大者；FRAME与GAP使用相同8帧段、步幅4、尾端对齐及固定8窗口外层归约。新增系数统一为0.0023821861727945912，由原有8个固定训练批次的梯度量级确定；FRAME/GAP的中位新增梯度分别为原C的25.0%/19.86%，没有用开发成绩调整。

两组均在8/8批提高sigmoid分数间隔、降低logit间隔；GAP在8/8批的分数间隔低于FRAME。目标响应确实改变，背景读出也随之抬升，不能表述为目标与背景的logit分离增强。训练代理变化未转化成GAP的额外严格匹配。详见[固定训练侧变化](resources/TRAINING_CHANGE_SUMMARY.md)。

集成并非无梯度：8个真实训练批次中，新项都向q+/q−、原TPro、conv_out1和conv_out2传回有限梯度。训练初态所采背景logit已很低；背景/目标读出梯度L2中位比仅约6.8×10⁻⁶（FRAME）和1.0×10⁻⁵（GAP）。在C2048初态的8个校准批次，新读出项与检测项的参数梯度余弦均为正、与保持项均为负，提示该状态下的局部优化冲突。这给出了值得修订的环节：现有背景均值读出给出的新增背景约束很弱，且存在局部保持冲突；不能据此推断整个训练过程的作用，也不能认定旧C失败的唯一原因。[梯度证据](resources/TRAINING_CONNECTION_REVIEW.json)保留逐批数值。

参考包24项CPU测试在本机重新通过；本地集成20项CPU测试通过，1项独立CUDA合成测试未运行，另以8个真实批次完成GPU原检测链校准。极端±1000数值测试属于CPU验证范围。[测试记录](resources/LOSS_VALIDATION.json)与完整[段缓存审计](resources/SEGMENT_CACHE_AUDIT.md)均已保存。共72,341个候选观察曝光，两路背景全部合法；15,591个段覆盖69,602个观察曝光、89个身份和全部8个训练来源。现有标注没有可见性/遮挡字段或额外标注完整性真值，因此实际验证的是连续有效标注段代理，以及已有标注覆盖内的背景排除。

SlotContrast和TrackMAE沿用[v1已核实来源](../track_contrast_v1/resources/REFERENCES.json)；本轮另核实了[DEIM官方MAL源码](https://github.com/Intellindust-AI-Lab/DEIM/blob/09d35d53d39ee3145a1e61e3a989b28b9468d1dd/engine/deim/deim_criterion.py)，仅借鉴直接联系检测读出的原则，其代码和参数没有进入训练。soft-OR来自本次用户方案，不能归为这些论文已经验证的公式。[DEIM来源记录](resources/DEIM_REFERENCE.json)包含固定提交与文件哈希。

当前证据支持保留已经接通的原检测读出监督，但应削弱连续段分组的必要性主张。尚未达到从发布权重扩展当前GAP长训、成对重复和新来源验证的条件，确认集未启用。下一项具体单因素候选是只修订新增项的困难背景读出：在同一合法背景ROI内使用发布教师预先固定峰位置的原logit，目标读出、原C三项及其权重、输入、分段和推理链全部保持。它检验背景均值是否把局部困难响应稀释，并须继续保留逐帧控制。本轮尚未测定同ROI峰值与均值的差距，弱背景梯度也可能来自当前负logit下的饱和；因此这是待验证的单因素候选，尚未实施或宣称有效。
